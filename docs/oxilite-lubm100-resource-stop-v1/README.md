# Oxilite LUBM-100 import resource stop

The Linux ARM64 Oxilite 0.10.0 import exceeded its 12 GiB container memory limit. The container recorded one OOM kill, peak memory reached 12,884,901,888 bytes, and the attach command exited 137. The worker produced no native triple count. The separate reopen process and all 30 aggregate query labels were skipped. The earlier nine-quad Linux qualification still applies to its three tiny profiles.

One registered attempt used a fresh SQLite file on a virtiofs bind mount and a read-only 2,377,133,547-byte LUBM-100 N-Triples input. The container had four CPUs and no extra swap allowance. Resource inspection passed. The supervisor confirmed container removal and rechecked input, runtime, source and lock after the stop. The original partial database and run receipts remain available locally.

The cgroup evidence identifies a memory limit stop for this import and configuration. It does not identify the allocation site, establish the memory required to complete the import, or provide query correctness or performance measurements. The elapsed stage time includes cleanup and is neither completed import time nor a benchmark score.

The saved cgroup counter files are byte copies from the run. The accompanying observations extract omits machine-local paths and the private message transcript. The preceding registration revisions never started a workload. The second revision failed during binding because it skipped the first message line. That was corrected before the one recorded attempt.
