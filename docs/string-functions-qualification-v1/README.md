# Independent qualification of string-function argument rules

Candidate `ef7a77814d23879a7bdf174ffe567b81a402ba9f` passes **122 targeted string/temporal controls** and **all 60 frozen BSBM BI100M requests**. The BI primary, COUNT-compatible and value-compatible checks all pass. Its RDF-term bags and sequences match the pinned baseline on every BI request. This is scoped regression evidence, not complete SPARQL conformance or a performance comparison.

The controls have independently specified expected RDF terms or unbound expression-error results, based on [W3C SPARQL 1.1 string functions](https://www.w3.org/TR/sparql11-query/#func-strings), [STRDT/STRLANG](https://www.w3.org/TR/sparql11-query/#func-strdt) and [dateTime extraction](https://www.w3.org/TR/sparql11-query/#func-year). They cover accepted string literal kinds, numeric/IRI/custom-datatype errors, asymmetric language compatibility, propagation and loss of tags, unmatched and empty substring searches, Unicode, COALESCE error recovery and five dateTime fields. This phase did not independently rerun the full W3C suite or use Jena to generate these small fixture answers.

Each fixture uses SELECT over the empty group. A type error must leave the projected variable unbound while preserving the solution row; the paired COALESCE check must recover its fallback value. Positive controls preserve STR on a number, an implemented cast, the noncanonical lexical form `"01"` constructed by STRDT, language-tag case handling and correct dateTime extraction. The fixed commit's earlier temporal regression was not observed on these controls.
