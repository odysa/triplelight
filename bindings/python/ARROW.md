# Arrow SELECT results (experimental)

Install the optional `arrow` extra (PyArrow), then call `db.query_arrow(sparql)` or `snapshot.query_arrow(sparql)`. Each returns a `pyarrow.RecordBatchReader`; SELECT variables are nullable Arrow struct columns:

- `kind`: `iri`, `bnode`, or `literal`.
- `value`: exact IRI, blank-node label, or literal lexical text.
- `datatype`: datatype IRI for literals; null for other terms.
- `language`: language tag if present; null otherwise.

A null struct is an unbound variable, distinct from a literal with an empty lexical value. These fields preserve RDF identity instead of coercing every numeric or date value into a Python value. `reader.read_all()` creates a PyArrow table; Pandas/Polars can import Arrow, but their handling of nested structs and nulls varies, and conversions are not promised to be zero-copy.

## Optional native value columns

`query_arrow(query, types="native")` is an opt-in analytical value view. When every bound term in a column is a literal of the same supported datatype and every value converts safely, it emits native Arrow `int64`, `decimal128` (at most 38 digits), `float32`, `float64`, `date32`, microsecond `timestamp`, or `large_string`; otherwise that entire column remains the lossless RDF struct. Unbound values remain null. Mixed timezone presence, greater-than-microsecond timestamp precision, unsupported dates, out-of-range integers/decimals, invalid lexicals, language tags and mixed term kinds/datatype fall back to structs. Native conversion intentionally drops original RDF lexical forms: e.g. `"01"^^xsd:integer` and `"1"^^xsd:integer` both become the integer 1. Use the default `types="rdf"` when exact term identity matters. Native inference currently scans the complete materialized Arrow result in Rust and constructs typed arrays; it is not a streaming, sidecar-backed or zero-copy operation. Timezoned dateTimes are normalized to UTC and lose their original offset; `24:00:00` and years outside 0001–9999 fall back to RDF structs. Derived integer types such as xsd:int and xsd:long currently fall back as well.

The implementation currently executes and materializes the full ID result, then decodes each distinct stored ID once per 8192-row batch and constructs Arrow-owned column buffers. The Arrow C stream interface transfers those buffers to PyArrow without copying the buffers; this is **not** a streaming query or zero-copy from the RDF dictionary, and memory grows with the result. ASK and graph queries are rejected. `db.export_parquet(query, path)` writes the same nested Arrow schema to Parquet; `types="native"` opts into the value view described above. `db.export_csv(query, path)` writes four columns per variable (`name.kind`, `.value`, `.datatype`, `.language`); an empty kind means unbound, so an empty literal value remains distinguishable. For nonliteral terms datatype/language are empty; datatype/language IRIs and tags cannot be empty for valid literals. CSV field names follow the SELECT variables and can be duplicated or contain dots, so consumers should retain column positions. Each export writes a temporary sibling and renames it over the destination after success; this is atomic publication on a supporting local filesystem, not an fsync durability guarantee. CSV currently materializes each Arrow batch as Python objects and is not a zero-copy path.
